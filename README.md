## Реализованная структура

### Серверная часть
- `app.js` — точка входа, настройка Express, Handlebars и статических файлов.
- `views/layouts/main.hbs` — общий layout-шаблон с подключением манифеста, стилей и Service Worker.
- `views/index.hbs` — главная страница с формой ввода секунд.
- `views/about.hbs` — страница «О себе» с информацией об авторе.
- `views/error.hbs` — шаблон страницы ошибки 404.

### Клиентская часть (статика)
- `public/css/style.css` — стили приложения.
- `public/js/main.js` — регистрация Service Worker и логика обращения к API.
- `public/manifest.json` — манифест PWA с иконками и метаданными.
- `public/sw.js` — Service Worker для кеширования и офлайн-работы.
- `public/icons/` — иконки приложения (192×192 и 512×512).

## Реализованные возможности

### Маршруты и ответы
- **GET /** — главная страница, отрендеренная через Handlebars с передачей данных (имя студента, серверное время).
- **GET /about** — страница «О себе» с информацией об авторе (ФИО, группа, институт, интересы).
- **GET /api/timer** — API-эндпоинт, возвращающий JSON с серверной меткой времени.

### Обработка параметров запроса
- Query-параметр `?seconds=60` задаёт длительность таймера.
- Валидация: параметр обязателен, должен быть положительным числом.
- Возврат **400 Bad Request** при отсутствии или невалидности параметра.
- Формат ответа: `{ start: ISO, end: ISO, durationSeconds: N }`.

### Шаблонизатор Handlebars
- Движок `express-handlebars` с layout-системой.
- Передача данных из сервера в шаблоны (`studentName`, `currentTime`, `group`).
- Разделение представления и логики: layout содержит общий каркас, страницы — только контент.
- Экранированный вывод (`{{title}}`) и сырой HTML (`{{{body}}}`).

### Progressive Web App (PWA)
- **Манифест** (`manifest.json`) с полями `name`, `short_name`, `start_url`, `display: standalone`, `theme_color`, `icons`.
- Приложение устанавливается на рабочий стол как нативное.
- Открывается без адресной строки браузера (режим `standalone`).

### Service Worker и офлайн-режим
- Регистрация SW через `navigator.serviceWorker.register('/sw.js')`.
- Событие `install`: кеширование статики (HTML, CSS, JS, манифест, иконки) в `caches.open()`.
- Событие `activate`: удаление устаревших кешей при обновлении версии.
- Событие `fetch`: стратегия Cache First — запросы сначала проверяются в кеше, затем идут в сеть.
- Приложение работает без подключения к интернету после первого посещения.

### Клиентский JavaScript
- Динамическое обращение к API через `fetch()` с `async/await`.
- Форматирование ответа сервера: преобразование ISO-дат в локальный формат.
- Визуальная индикация успеха/ошибки через CSS-классы (`success`, `error`).
- Обработка сетевых ошибок с понятным сообщением для пользователя.

### Обработка ошибок
- **400** — невалидный или отсутствующий параметр `seconds`.
- **404** — несуществующий маршрут (кастомная страница через Handlebars).
- **500** — внутренние ошибки сервера (логирование в консоль).
- Graceful degradation: если Service Worker не поддерживается браузером, приложение продолжает работать.

## Логика работы приложения

### При загрузке страницы
1. Express рендерит шаблон через Handlebars, подставляя данные из сервера.
2. Браузер загружает HTML, находит `<link rel="manifest">` и скачивает `manifest.json`.
3. Выполняется `main.js`: регистрируется Service Worker, который кеширует статику.
4. Пользователь видит форму ввода секунд и кнопку «Получить время с сервера».

### Работа с API таймера
1. Пользователь вводит количество секунд и нажимает кнопку.
2. Клиентский JS отправляет GET-запрос на `/api/timer?seconds=N`.
3. Сервер валидирует параметр:
   - Если параметр отсутствует → 400.
   - Если не число или ≤ 0 → 400.
4. Сервер вычисляет `start = new Date()` и `end = start + N * 1000 мс`.
5. Возвращается JSON с ISO-форматом времени начала, конца и длительностью.
6. Клиент форматирует даты в локальный вид и отображает результат.

### Офлайн-режим
1. При первом посещении Service Worker кеширует все статические ресурсы.
2. При отключении интернета браузер перехватывает запросы через SW.
3. SW отдаёт файлы из кеша — страница загружается полностью.
4. API-запросы в офлайне возвращают сетевую ошибку (API не кешируется).

## Инструменты и технологии

- **Node.js** — среда выполнения JavaScript на сервере.
- **Express** — веб-фреймворк для маршрутизации и обработки запросов.
- **Handlebars (express-handlebars)** — шаблонизатор для динамического рендеринга HTML.
- **Service Worker API** — фоновый скрипт для кеширования и офлайн-работы.
- **Cache API** — хранилище ресурсов для Service Worker.
- **Web App Manifest** — стандарт PWA для установки приложения.
- **npm** — менеджер пакетов для установки зависимостей.
- **nodemon** — утилита для автоматического перезапуска сервера при разработке.
